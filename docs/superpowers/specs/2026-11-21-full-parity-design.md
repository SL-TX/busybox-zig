# BusyBox 1.39.0 → Zig: Full Parity Design

Дата: 2026-11-21
Статус: проект спецификации, на утверждение
Референс: `reference/busybox`, git `6412da255d465be1f1860ae109ccbf2564810af2`
(`VERSION=1 PATCHLEVEL=39 SUBLEVEL=0 EXTRAVERSION=.git`)

## Intent

Довести `busybox-zig` до состояния, в котором он является заменой
референсному BusyBox 1.39.0 для одного статического бинарного файла: тот же
набор апплетов, те же параметры командной строки, тот же вывод, те же коды
возврата, та же конфигурация, та же мета-командная строка `busybox` и та же
семантика привилегий.

Это не «скелет с заглушками» и не «частичная совместимость». Критерий
готовности — измеримый: дифференциальные тесты каждого апплета против
референсного бинарника проходят, заглушек нет.

## Что считается полным паритетом

Паритет определяется следующими проверяемыми контрактами.

### 1. Набор апплетов

- При конфигурации, повторяющей `make defconfig` референса, `busybox --list`
  совпадает с референсом: **412** апплетов, без лишних и без пропущенных.
- При конфигурации «включено всё» доступны все **443** имени апплетов из
  референсного дерева (включая алиасы `[`, `[[`, `sh`, `w` и т. п.).
- В реестре нет «внутренних» имён, которые не являются апплетами. Сейчас там
  46 таких записей (`tls_*`, `tcpudp`, `isrv`, `httpd_ssi`, `interface`,
  `zlib`, `zcmp` и др.) — они должны исчезнуть из `--list`.

### 2. Метаданные апплетов

Для каждого апплета совпадают:

- расположение ссылки при установке (`/bin`, `/sbin`, `/usr/bin`,
  `/usr/sbin`) и вывод `busybox --list-full`;
- тип SUID (`BB_SUID_DROP`, `BB_SUID_REQUIRE`, `BB_SUID_MAYBE`) и поведение
  при запуске от непривилегированного пользователя;
- флаги `NOEXEC`, `NOFORK`, `SCRIPTED`;
- текст `APPLET --help` (979 usage-блоков в референсе).

### 3. Мета-командная строка `busybox`

Совпадают поведение и вывод:

- `busybox` без аргументов;
- `busybox --help [APPLET]`;
- `busybox --list`, `busybox --list-full`;
- `busybox --show SCRIPT` (при `FEATURE_SHOW_SCRIPT`);
- `busybox --install [-s] [DIR]` (при `FEATURE_INSTALLER`);
- специальные случаи `test --help`, `true --help`, `false --help`,
  `echo --help`, `[ --help`, `[[ --help`;
- `busybox --version` — только banner `BusyBox v1.39.0...` (не 1.36.1);
- выбор апплета по `argv[0]` и по первому аргументу.

### 4. Поведение апплетов

Для каждого апплета дифференциальный тест запускает одинаковые команды
против референса и Zig-бинарника в одинаковой песочнице и сравнивает:

- stdout побайтно;
- stderr побайтно (с нормализацией путей/pid/времени, где это неизбежно);
- код возврата;
- созданные/изменённые/удалённые файлы, их содержимое, права, владельца и
  symlink-цели;
- сигналы и таймауты для интерактивных и фоновых режимов.

Покрываются все документированные опции, комбинации опций, отсутствующие
аргументы, неверные опции, stdin/file/dir-режимы и хотя бы один граничный
случай на опцию. Поведение апплета задаётся его C-исходником в
`reference/busybox`; спецификация не переписывает его своими словами.

### 5. Конфигурация

- Все **946** символов `.config` референса представлены: 895 boolean и 51
  не-boolean.
- Значения по умолчанию совпадают с референсным `defconfig`.
- Отключённый апплет не попадает в бинарник и в `--list`.
- Feature-флаги (`FEATURE_*`, `LONG_OPTS`, `DESKTOP`, `SH_STANDALONE` и т. д.)
  реально управляют кодом, а не игнорируются.
- Конфигурация генерируется из текстового `.config`; интерактивный
  `menuconfig` не входит в паритет (это инструмент сборки, а не поведение
  бинарника).

### 6. Отсутствие заглушек

В финальной сборке с полной конфигурацией ни один апплет не печатает
`not implemented`. Временные заглушки допустимы только в промежуточных
волнах и обязаны быть видны в матрице паритета.

### 7. Ограничения реализации

- Один статический бинарник `busybox`, Linux x86_64, Zig 0.17.1.
- Никакого C-кода в бинарнике: не линкуем C-реализации апплетов и libbb,
  не вызываем системные утилиты вместо реализации.
- Kernel UAPI-константы и структуры могут быть переписаны в Zig или взяты
  через `@cImport` только для заголовков, не для кода.
- Лицензия GPLv2+.

### Известные функциональные пробелы у 43 «реализованных»

Ни один из 43 апплетов не проходил аудит паритета. Из журнала выполнения
уже известны крупные пробелы:

- `sed`/`awk`: нет POSIX BRE/ERE, полноценных выражений и большинства команд.
- shell: нет пайпов, перенаправлений, globbing, управляющих конструкций,
  job control и интерактивного TTY.
- networking: нет DNS, TLS, raw-socket ping, httpd, udhcpc, telnetd и др.
- `ps`/`top`: неполный набор опций, `top` не интерактивный.
- `loginutils`: только MD5-crypt, нет SHA-crypt/DES, нет PAM/TTY-промптов.
- `mount`/`umount`/`ifconfig`/`nc`/`wget`: частичные реализации.
- `cp`/`rm`/`find`/`grep`/`ls`/`cat` и др.: неполный набор опций.

## Goals

1. Реализовать все 443 апплета с поведением, совпадающим с референсом.
2. Привести реестр, метаданные, usage-тексты и мета-CLI к референсу.
3. Сгенерировать полную конфигурацию из 946 символов и подключить feature-флаги.
4. Портировать libbb-хелперы, нужные этим апплетам, с unit-тестами.
5. Построить дифференциальный тестовый стенд и покрыть им каждый апплет.
6. Сделать CI, который ловит расхождения с референсом и устаревание манифеста.

## Non-Goals

- Оптимизация размера и скорости бинарника.
- Поддержка архитектур кроме x86_64 и ОС кроме Linux.
- Интерактивный `menuconfig`/Kconfig-фронтенд.
- Побайтовая идентичность ELF-бинарника референсу.
- Новые апплеты и опции, которых нет в референсе.
- Точное воспроизведение неопределённого поведения и текстов падений C-кода;
  для UB фиксируется класс поведения (ненулевой код, сообщение об ошибке),
  а не точный segfault-вывод.
- Локализация: в BusyBox её нет.

## Anti-Goals

- Линковать C-код BusyBox или вызывать системные `busybox`/`coreutils`.
- Оставить заглушки в финальной сборке.
- Разделить апплеты на отдельные бинарники.
- Выбросить апплеты или опции «потому что сложно».
- Подменить поведение «похожим» вместо референсного.

## Constraints

- Zig 0.17.1, Linux x86_64, статическая сборка.
- Референс закреплён коммитом `6412da2`; обновление референса — отдельное
  решение, а не побочный эффект.
- Сборка и тесты не должны требовать сети; референсный бинарник для CI
  собирается заранее или заменяется закоммиченными golden-файлами.
- Тесты не должны трогать реальные `/etc/passwd`, `/etc/shadow`, диски,
  сетевые интерфейсы и системные сервисы.
- Привилегированные сценарии выполняются в контейнере/namespace с явно
  выданными capability, а не на хосте.

## Approaches

| Подход | Описание | Плюсы | Минусы |
|---|---|---|---|
| **A. Сначала весь libbb** | Портировать 158 C-файлов libbb, потом апплеты | Фундамент готов заранее | Месяцы без видимого результата; хелперы пишутся «на всякий случай» и переделываются |
| **B. Апплет за апплетом** | Брать апплет, дописывать нужные хелперы по месту | Быстрый видимый прогресс | Дублирование, разъезжается семантика, нет общей картины |
| **C. Манифест + дифференциальный стенд, затем волны** | Сначала генерация манифеста/конфига/usage и стенд, затем категории волнами; libbb-хелперы добавляются под волну | Прогресс измерим, расхождения ловятся сразу, нет спекулятивного кода | Требует вложиться в инфраструктуру до первого апплета |

**Выбран C.** Он даёт измеримый критерий готовности, не требует писать весь
libbb вслепую и не позволяет «похожей» реализации пройти незамеченной.
Подход A отпадает из-за отсутствия обратной связи, B — из-за дрейфа
семантики и дублирования.

## The How — принятые решения

### 1. Единый источник истины — манифест из референса

Скрипт `scripts/parity/extract_manifest.py` разбирает
`//applet:IF_*(APPLET...)` и `//usage:` в `reference/busybox` и генерирует:

- `src/generated/applet_manifest.zig` — имя, config-флаг, location, suid,
  noexec/nofork/scripted, ссылка на usage;
- `docs/superpowers/specs/2026-11-21-busybox-parity-matrix.md` — матрица
  статусов;
- `tests/parity/manifest.json` — тот же манифест для тестового стенда.

CI перегенерирует манифест и падает, если закоммиченные файлы отличаются.
Ручной список апплетов в `src/applets.zig` больше не является источником
имён; он только сопоставляет имя с функцией `main`.

### 2. Метаданные апплета

`Applet` расширяется до:

```zig
pub const Location = enum { bin, sbin, usr_bin, usr_sbin };
pub const Suid = enum { drop, require, maybe };

pub const Applet = struct {
    name: []const u8,
    main: MainFn,
    location: Location,
    suid: Suid,
    noexec: bool = false,
    nofork: bool = false,
    scripted: bool = false,
    usage: []const u8,
};
```

Диспетчер применяет `suid` так же, как `libbb/appletlib.c`: `require` —
отказ непривилегированному пользователю; `drop` — сброс euid/egid до
реальных; `maybe` — поведение референса. `--install` использует `location`.

### 3. Конфигурация

- `configs/defconfig` — копия референсного `.config` (defconfig), закоммичена.
- `scripts/parity/gen_config.py` генерирует `src/generated/config.zig` со
  всеми 946 символами в виде `pub const CONFIG_<SYMBOL> = ...;`.
- Для совместимости с текущим кодом генерируются алиасы
  `pub const APPLET_<name> = CONFIG_<FLAG>;`.
- `zig build -Dconfig=path/to/.config` выбирает конфигурацию; по умолчанию
  используется `configs/defconfig`.
- Feature-флаги читаются кодом через `config.CONFIG_FEATURE_*` и влияют на
  поведение и наличие кода.

### 4. Usage-тексты

Точный текст `APPLET --help` снимается с референсного бинарника
(`scripts/parity/extract_usage.py`) и генерируется в
`src/generated/usage.zig`. Это надёжнее, чем разбирать C-препроцессор
`//usage:`-блоков, и гарантирует побайтовое совпадение. Сгенерированный файл
коммитится; CI проверяет его свежесть.

### 5. libbb_zig

Модули разбиваются по ответственности, а не по одному файлу на C-файл:

- `xfuncs.zig`, `messages.zig` — die/warn/perror, xmalloc, xstrdup;
- `getopt.zig` — полный `getopt32`, включая long options, `-abc`, optional args;
- `string.zig`, `path.zig`, `env.zig`, `util.zig` — строки, пути, env, числа;
- `process.zig`, `signals.zig`, `identity.zig`, `utmp.zig` — fork/exec/wait,
  сигналы, setuid/setgid/groups, utmp/wtmp, daemon/vfork;
- `io.zig`, `file.zig`, `recursive.zig`, `copy.zig` — полный read/write,
  copy_file/copyfd, recursive_action, remove_file, make_directory;
- `crypto/` — MD5, SHA1, SHA256, SHA512, SHA3, DES, yescrypt-совместимый
  `pw_encrypt`, CRC32, HMAC, base64/uuencode;
- `regex/` — собственный POSIX BRE/ERE-движок на Zig (нужен для grep, sed,
  awk, vi, less, pgrep, ps и др.);
- `compression/` — gzip/zlib, bzip2, xz/lzma, lzop, unlzma;
- `archive/` — tar, cpio, rpm, dpkg-deb;
- `net/` — сокеты, DNS-резолвер, TCP/UDP-серверы, HTTP, TLS, DHCP;
- `term/` — termios, консоль, клавиатура, шрифты, framebuffer, pty;
- `login/` — passwd/shadow/group, crypt, securetty, update_passwd;
- `selinux.zig` — xattr/label-операции для SELinux-апплетов.

Правило: хелпер добавляется тогда, когда его требует текущая волна, и
сразу покрывается unit-тестом. Список «портировать всё из libbb» не
составляется.

### 6. Дифференциальный стенд

- `tests/parity/cases/<category>/<applet>.json` — кейсы: argv, stdin, файлы,
  env, cwd, timeout, ожидаемые side effects.
- `scripts/parity/run.py` — материализует две одинаковые песочницы, запускает
  референс и Zig, сравнивает stdout/stderr/exit/дерево файлов.
- Нормализация: `<TMP>`, pid, uid/gid, hostname, время, сортировка строк —
  только там, где значение неизбежно недетерминировано; каждая нормализация
  указывается в кейсе явно.
- `--golden` — режим для CI без референсного бинарника: сравнение с
  закоммиченными golden-файлами.
- `scripts/parity/pty.py` — pty-сценарии для `vi`, `top`, `login`, `passwd`,
  `more`, `less`, `script` и интерактивных оболочек.
- `scripts/parity/ns.py` — запуск в network/mount/pid namespace, tmpfs и
  loop-образах для сетевых, mount и файловых апплетов.
- Разрушительные и привилегированные кейсы помечаются `requires` и
  выполняются только в контейнере с нужными capability.

| Волна | Содержимое | Апплетов | Предусловие |
|---|---|---:|---|
| 0 | Манифест, конфиг, метаданные, usage, стенд | 0 | — |
| 1 | coreutils + findutils + debianutils + printutils + klibc + arch | 113 | libbb core |
| 2 | util-linux + e2fsprogs + modutils | 83 | libbb filesystem/crypto/term |
| 3 | networking + mailutils | 63 | libbb net/DNS/TLS |
| 4 | miscutils + procps + console-tools | 98 | libbb process/term |
| 5 | archival | 24 | libbb compression/archive |
| 6 | shell | 5 | libbb regex/term |
| 7 | loginutils + selinux | 27 | libbb crypto/login/selinux |
| 8 | init + sysklogd + runit + editors + libbb-апплеты | 30 | libbb process/term/regex |
| 9 | Паритетная доводка и релиз | 443 | все волны |

### 8. Критерий готовности волны

- Все апплеты волны зарегистрированы и не являются заглушками (для
  default-enabled; отключённые конфигом — компилируются, но не входят в
  бинарник).
- Для каждого апплета есть дифференциальные кейсы, покрывающие usage,
  опции, ошибки и граничные случаи.
- `--help` совпадает с референсом.
- `zig build test` и `python3 scripts/parity/run.py --all` зелёные.
- Матрица паритета обновлена, CI проверяет её свежесть.

## Acceptance Criteria

Проект считается достигшим полного паритета, когда одновременно выполнено:

1. `busybox --list` для defconfig побайтово (после сортировки) равен
   референсу; для all-on конфигурации — 443 имени.
2. `busybox --list-full` и установленные symlink-и совпадают с референсом.
3. Все мета-опции `busybox` (`--help`, `--list`, `--list-full`, `--show`,
   `--install`, `--version`) и `APPLET --help` совпадают с референсом,
   включая специальные случаи `test`/`true`/`false`/`echo`/`[`/`[[`.
4. Для всех 443 апплетов дифференциальные тесты проходят; для 412
   default-enabled — без `requires`-пропусков, кроме явно задокументированных
   environment-ограничений.
5. В финальной all-on сборке нет `not implemented`.
6. Все 946 config-символов сгенерированы; feature-флаги меняют поведение;
   отключение апплета убирает его из бинарника и `--list`.
7. `zig build`, `zig build test`, parity-golden и parity-reference в CI
   зелёные.
8. В бинарнике нет C-кода и вызовов внешних утилит вместо реализации.

## Risks and Mitigations

| Риск | Почему опасен | mitigation |
|---|---|---|
| Масштаб: 283k C LOC | Оценка «доделать за пару задач» нереалистична | Волны, генерация, дифференциальный стенд, явная матрица |
| POSIX regex | Нужен grep/sed/awk/vi/less; в Zig нет готового | Отдельный движок с тестами против reference; ранний прототип в волне 6 |
| Compression/TLS/archive | Крупные самостоятельные подсистемы | Выделенные задачи, golden-тесты на реальных файлах, fuzz |
| TTY/daemons | Нельзя проверить обычным запуском | pty-стенд, namespace-стенд, явные `requires` |
| Привилегированные тесты | Риск для хоста | Только контейнер с capability, tmpfs/loop, никаких реальных `/etc` |
| Config drift | Ручной список уже разошёлся с референсом | Генерация + CI-проверка свежести |
| «Похожее» поведение | Пользователь получит тихо другой результат | Дифференциальные тесты, а не только unit-тесты |
| Обновление референса | Матрица и golden устареют | Референс закреплён коммитом; обновление — отдельная задача |

## Calls I made (решения, которые можно оспорить)

1. **Референс — 1.39.0 (коммит `6412da2`), а не 1.36.1.** Текущая
   спецификация и `--version` называют 1.36.1, но `reference/busybox` — это
   1.39.0.git. Целимся в то, что реально лежит в референсе.
2. **Цель — все 443 имени, default-конфигурация — 412.** Отключённые в
   defconfig апплеты (SELinux, `ar`, `unit`, `busybox`) должны собираться при
   включении флага.
3. **Kconfig-фронтенд не портируется.** Паритет — по символам и значениям
   `.config`, а не по интерактивному меню.
4. **Usage-тексты снимаются с референсного бинарника**, а не парсятся из
   `//usage:`-блоков.
5. **Дифференциальный стенд — обязательная часть Definition of Done**, а не
   «дополнительное тестирование».
6. **Собственный regex-движок на Zig.** Линковать libc regex нельзя: это
   C-код в бинарнике и конфликт с anti-goal.
7. **Один апплет — один файл** для крупных апплетов; мелкие (`true`,
   `false`, `yes`) могут группироваться, но с отдельными `main` и тестами.
8. **Интерактивные и привилегированные кейсы не пропускаются молча.**
   Пропуск допустим только с явным `requires` и записью в отчёте.
